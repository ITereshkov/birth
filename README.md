# ФинАгент (Telegram-бот)

Telegram-бот для личных финансов на **Python 3.11+ / aiogram 3.x**:
- кнопочный UX как в мини-приложении;
- учёт доходов/расходов;
- итоги по периодам;
- бесплатный Excel-экспорт, ИИ-анализ и уведомления;
- изоляция данных: отдельная SQLite-БД на каждого пользователя.

## Стек
- Python 3.11+
- aiogram 3.15
- SQLite (per-user)
- openpyxl
- OpenAI API (опционально)

## Быстрый запуск (локально)

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate.bat
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполните .env
python -m app.main
```

## ENV
- `BOT_TOKEN` — обязательно
- `OPENAI_API_KEY` — опционально
- `CONSULT_URL` — ссылка на консультацию
- `ADMIN_IDS` — опционально
- `DATA_DIR` — по умолчанию `data`


## ИИ-отчёт через OpenRouter (ChatGPT-совместимо)
Для команды `/analize` можно использовать OpenRouter.

Добавьте в `.env`:
- `OPENROUTER_API_KEY=ваш_ключ`
- `OPENROUTER_MODEL=openai/gpt-oss-120b:free` (можно заменить на другую модель OpenRouter)

Логика такая:
1. Если задан `OPENROUTER_API_KEY` — бот делает ИИ-отчёт через OpenRouter API.
2. Если OpenRouter не задан/недоступен, но есть `OPENAI_API_KEY` — fallback на OpenAI.
3. Если нет ни одного ключа — бот возвращает сообщение о недоступности ИИ-анализа.

## Команды
- `/start` — онбординг + меню
- `/help`
- `/balance` — экран итогов
- `/export` — Excel
- `/analize` — ИИ-анализ
- `/premium` — статус (сейчас все функции бесплатны)
- `/consult` — ссылка на консультацию

## Что поменяли в UX
- Убрали запрос таймзоны из `/start`.
- Главное меню всегда под рукой (reply keyboard).
- Базовый сценарий: кнопка типа операции → сумма → категория кнопками.
- Категории показываются кнопками с пагинацией и кнопкой “➕ Новая категория”.
- После сохранения — понятное подтверждение и быстрые действия.

## Почему раньше итоги могли быть нулевыми
Раньше фильтрация опиралась на datetime (и локальные/наивные значения времени), из-за этого свежая операция могла не попасть в «Сегодня».

### Исправление
Теперь у каждой операции есть:
- `occurred_at_utc` — datetime в UTC;
- `occurred_date` — дата в Europe/Moscow.

Отчёты и периодные фильтры (`Сегодня/Неделя/Месяц/даты`) считаются по `occurred_date`, поэтому только что добавленная запись гарантированно попадает в итоги нужного периода.

## Ошибка на Windows: `No time zone found with key Europe/Moscow`
Если видите ошибку `ZoneInfoNotFoundError`, выполните:
```bash
pip install tzdata
```
И перезапустите бота. В коде также добавлен fallback на UTC+3, чтобы бот стартовал даже без системной tz-базы.
